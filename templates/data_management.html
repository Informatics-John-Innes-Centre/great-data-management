Data Management Guide

From the JIC Data Management course — where to store your data, good habits, and how to look after it.

Here your data is NOT safe
  • Instruments and the computers attached to them
  • Employee devices — laptops, desktops, phones, etc.
  • External devices — hard drives, USB sticks, SD cards

These are not backed up by IT. If it only exists here, it can be lost for good.

Use these instead — backed up by IT
  • U drive (\\nbi-ufiles\username) — up to 20 GB, good for personal documents that don't need sharing.
  • OneDrive and SharePoint — for documents that need to be shared or synced across devices.
  • Computing shared storage (\\nbi-cfs2) — good for shared documents like protocols and SOPs; small quota, not for big data.
  • HPC storage / Isilon (\\jic-hpc-data) — the right place for research data, including everything tracked on this dashboard.

Good habits

  • Treat raw data as read-only — work on copies, never edit the original file.
  • A single copy is a single point of failure. Automate backups in more than one place — a snapshot is not a backup.
  • Don't run heavy I/O analysis jobs directly in a Group folder — use a Scratch area for that instead.
  • Avoid cryptic filenames like new_final2_real.bam — use clear, consistent naming.
  • Document sample origins, processing steps, and tool versions — unlabelled data becomes unusable, even to you a year later.

Metadata: don't leave your data unlabelled

Your final results are only as useful as your documentation. Without metadata, even you won't remember what a dataset was, where it came from, or how it was produced a year from now.

At minimum, document:

  • Data sources and versions
  • Parameters and tools used, including their versions
  • The rationale behind any choices made, and known caveats

Recovering deleted or modified files

The Isilon automatically takes snapshots of data (retention varies by folder). If you've just deleted or overwritten something, the chances of recovering it are high — the longer you wait, the lower the chances get. Permissions on a snapshot are identical to the original data, and snapshots can be browsed from any device — the best way to find what's available is to look through the snapshot folders directly.

Sharing data with collaborators

  • Small files — OneDrive/SharePoint
  • Up to 300 GB — Dropoff, easy web-based transfer
  • Large or recurring transfers — Globus, no practical size limit

The ideal data pipeline

Raw data and results, with proper metadata, belong in an Archive area once you're done actively working with them, ready to feed an online repository or publication. Scripts and workflows live in your HPC home directory, kept under version control (GitHub, GitLab) rather than as loose files only you can see — that way your line manager and colleagues can access them too, not just you. Heavy intermediate files that don't need to last belong in Scratch — and should be removed once you're finished with them. That's exactly what the "Legacy / Scratch / Archive" areas tracked on this dashboard are for.

Practice: the path game

Want to get comfortable with relative and absolute filesystem paths? Try nbipath, a small terminal game for exactly that — github.com/Informatics-John-Innes-Centre/nbipath.
